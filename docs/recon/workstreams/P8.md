## Decisions

### D8-001 · 2026-11-27 · What a P8 code would unlock is counted from the codes it rides with

The D-060 records (P7's `phase7-final-d060.jsonl`, read only) give each open function every code its choices met, primary
first. A primary code is only the first in pipeline order; within the Knowledge family codes sort by name, so
`CALLEE_SIGNATURE_UNKNOWN` comes before `CLASS_NOT_DECLARED`, `INDIRECT_CALL` and `MEMBER_NOT_DECLARED`. Removing a
primary code moves a function on only when nothing else blocks it. Counted on the development set:

|---|---|---|---|
| `CALLEE_SIGNATURE_UNKNOWN` | 706 | 121 | `LOCAL_IN_MEMORY` 278, `INDIRECT_CALL` 205, `ADDRESS_VALUE` 61 |
| `INDIRECT_CALL` | 352 | 352 | |
| `MEMBER_NOT_DECLARED` | 245 | 245 | (a candidate exists; the member form refuses it) |
| `CLASS_NOT_DECLARED` | 212 | 212 | (as above) |
| `CALLEE_NOT_DECLARED` | 134 | 134 | (as above) |
| `READS_A_LOCATION_NOBODY_SET` | 100 | 13 | `CALLEE_SIGNATURE_UNKNOWN` 87 |

Held-out (aggregate): `CALLEE_SIGNATURE_UNKNOWN` 26 primary, 4 alone; `READS_A_LOCATION_NOBODY_SET` 5, 4 of them with
`CALLEE_SIGNATURE_UNKNOWN`.

Of the 121 development functions held only by unknown callee signatures, decoded from the image: **67 make no call and
end in one tail jump** to a direct target; 64 are under 32 bytes. A tail jump is no call site (`call_sites` leaves tails
out, D-051), so nothing a forwarder's callers do is evidence for the function it forwards to, and if that function's own
code tells nothing and its other callers are forwarders too, it has no reading at all.

The order of work stays the charter's (signatures first): it is the largest count, and it is also the code that, read
off callers, `READS_A_LOCATION_NOBODY_SET` depends on (D-053). The member-form codes are 591 functions that already have
a candidate and are next.

### D8-002 · 2026-11-27 · A function its own code cannot read is read from its call sites, through forwarders, and a contradiction blocks

Design, to land after C0 (it changes `core/inference/whole.py`):

* **Facts with a status.** A signature carries how it is known: `declared` (an upstream or platform declaration),
  `inferred` (its own code), `constrained` (its call sites, all agreeing), `ambiguous` (call sites that agree on a
  reading but leave a choice open), `contradicted` (call sites that disagree). A contradicted signature is no signature:
  the functions that need it are blocked, never given one side.
* **Call-site evidence, positive and negative.** At a call, a location is *set* when it holds a value of the caller's
  own (D-053's rule) and *left* when it holds what an earlier call left there or nothing the caller ever set: then the
  caller cannot mean it as an argument. A position is a parameter when some caller sets it and no caller leaves it;
  set by one caller and left by another is a contradiction. A result is read when any caller uses it; one caller reading
  an integer result and another a floating one is a contradiction.
* **Through forwarders.** A function that ends in a tail jump passes on what its callers gave it. Each tail jump is
  read like a site (what the forwarder sets itself, which of its entry locations it passes on unchanged and where to),
  and each call of the forwarder becomes a site of the function it forwards to.
* **In the worklist.** When a function's own code gives no signature, its call sites give it one, so the functions
  above it are read from their own code again instead of failing in a chain. What call sites say depends only on the
  callers' normal forms (never on their signatures), so the bottom-up order still holds; the key of such a signature
  digests its callers' keys and the index of callers, so a change in a caller invalidates exactly that.

### D8-003 · 2026-11-27 · Why a signature is unknown is walked down to where the chain starts

`core/inference/explain.py` asks a program why it has no signature for a function: it follows every callee without one,
once, down to the functions whose own code is the cause, and names each by the fixed code that stops it there
(`normal:<code>` when its normal form is refused, `reading:<code>` when its reading is, `cycle` when a cycle does not
settle). It changes nothing the program knows. `through_tail` finds the one function a forwarder jumps to.

Run on the 47 of the 67 forwarders of D8-001 that a lazily filled private store had reached (development set, targeted,
read through `phase7-final-d060.jsonl` and the image only): every one is unknown through a chain of depth 7 to 15, and all
of them run into the same few functions. 24 distinct roots in all; the five that every one of the 47 reaches are refused
for `STACK_NOT_BALANCED_AT_EXIT` (normal form), `LOCAL_IN_MEMORY` (two), `READS_A_LOCATION_NOBODY_SET` (reading) and
`HANDLER_NOT_UNDERSTOOD` (normal form); the next are two tail jumps through a value (`INDIRECT_CALL`) and two more
`LOCAL_IN_MEMORY`. A handful of widely called functions decide the signatures of most of the program above them.

A second sample, 41 of the 706 development functions whose primary code is `CALLEE_SIGNATURE_UNKNOWN` (every 17th, each
explained under a budget of level 1; targeted): 114 distinct roots; 13 of the 41 have only body-only roots
(`LOCAL_IN_MEMORY`, `READS_A_LOCATION_NOBODY_SET`, `VECTOR_VALUE`, see D8-004), and 21 reach the same two machine-refused
hubs as the forwarders (`STACK_NOT_BALANCED_AT_EXIT`, `HANDLER_NOT_UNDERSTOOD`). Roots by code, counted once per
function that reaches them: `READS_A_LOCATION_NOBODY_SET` 32, `LOCAL_IN_MEMORY` 28, `STACK_NOT_BALANCED_AT_EXIT` 21,
`HANDLER_NOT_UNDERSTOOD` 21, `INDIRECT_CALL` (a tail jump through a value) 18, `CONFLICTING_EVIDENCE` 6, others 1 to 3.
A root removed may show the next one below it, so these bound what D8-004 and D8-002 can do; they do not predict it.

### D8-004 · 2026-11-27 · A function's interface does not wait for its body

`Program._infer` read a signature through `lower`, which refuses a body with a local whose address leaves the function
(`LOCAL_IN_MEMORY`), a vector value (`VECTOR_VALUE`) or a read of a location nobody set
(`READS_A_LOCATION_NOBODY_SET`). Each check runs after the parameters are fixed, and none changes them: they say what the
source cannot write yet, not what the function takes. So a callee whose body has a local in memory had no signature, and
neither had anything above it (D8-003: two of the five roots every forwarder reaches). `lower.interface` gives the
parameters `lower` computes without those three checks (`BODY_ONLY`); the reading of a signature uses it (in `whole.py`,
after C0), and the body of a target is still lowered, and refused, as before. Anything that does decide the parameters
(a callee without a signature, an argument on the stack, a parameter in two locations, a preserved register changed) still
refuses the interface.

### D8-005 · 2026-11-27 · Call-site evidence is read in a module of its own, filed with the analysis

The evidence of D8-002 is read off each caller's normal form by `core/inference/callsites.py` (`call_evidence`): per direct
call, the locations the caller sets (a constant with width 0, since it takes its parameter's width; a value with the width
it wrote, seen through a pair to its low part), the locations it leaves (`left_behind`: undefined, or what an earlier call
left outside its result, through merges as a greatest fixed point), and the results it reads. `core/inference/evidence.py`
has the statuses and `from_sites`.

A first version put this into `sites.call_sites`. That moves the site namespace (`SITE_ROOTS`), and with it the sites,
callees and index of callers of all 114,652 functions, which the next prewarm then reads again from every normal form:
hours in the development lane before a single targeted run, and again at P7's next checkpoint. Evidence is needed only
for the callers of a function whose own code gives no signature, so it is its own kind (`evidence`), keyed by the caller's
extent and filed under the analysis namespace (`*`), computed when first asked and kept. `sites.py` is unchanged, so
every stored site, callee and index of callers stays valid.

The forwarder part of D8-002 is deferred: D8-003 measured that 58 of the 67 forwarders and the functions they forward to
have no direct caller at all (only vtables hold them), so a forwarder's callers would add no evidence for them. The
worklist change waits for C0.
