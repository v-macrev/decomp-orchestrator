## Decisions (D9-NNN)

**D9-001 (2026-11-27) The kind list.** Ten kinds in `core/synthesis/kinds.py` (`KINDS_VERSION` 1), in precedence order: size-only,
register-assignment, branch-polarity, block-order, stack-layout, unwind, extension, constant-materialisation, call-relocation,
instruction-selection. Code `MISMATCH_<KIND>`, name `MISMATCH(<kind>)`. Comparator reasons keep their own `MISMATCH(<reason>)`.
A member-offset difference counts as constant-materialisation (no separate kind: it is P8 knowledge, not a synthesis rule).

**D9-002 The classifier.** `adapters/x64_msvc/mismatch.py` reads only the two instruction streams. Whole-function
explanations first (same tokens with other encodings or padding; a consistent GPR renaming; the same basic blocks rearranged,
polarity when a matched block's condition flips; equal modulo frame offsets), else difflib alignment and a kind per differing
instruction; the kind covering most instructions is primary, ties by precedence. A frame-size change goes with unwind when
saves differ, else with stack layout. Mirrored comparisons are polarity; a zeroing before a set-on-condition is extension.

**D9-003 The knowledge base.** Twelve rules (`core/synthesis/rules.py`, `RULES_VERSION` 1), one per change the generator can
make, so every rule is applicable by the search today. Each is confirmed under `msvc-19.16.27054-o2` by compiling original pairs
(`tests/fixtures/cpp/p9_rules.cpp`, 23 pairs: at least two positive per rule, primary kind in the rule's `effect`; negatives
compile identically). `related` kinds come from upstream's cookbook (rule numbers cited, no RVA copied). Cookbook rules that
need new emitter forms (tail-call narrowing, xor versus immediate stores, local declaration order for stack layout) are not
rules yet: no generator dimension makes them.

**D9-004 The queue.** Nodes are judged candidates keyed (tier, distance, trail length, tree digest, sequence). Tier 0 expands
the families `FAMILIES[kind]` maps to; tier 1 the other families of the same node, after every tier-0 node. Unknown kind (no
classifier, a failed compile, the canonical form refused) expands everything in tier 0. Equal trees and equal objects are
not expanded twice. Trails stop at `MAX_TRAIL` 6. A verified-but-failed candidate is expanded by the kind its comparator
reason names (unwind, call-relocation, size-only). Completeness is kept (tier 1), so a function the old two-stage generator
reached is still reachable; only the order and the budget level that reaches it can change. The regression run decides.

**D9-005 Plausibility before compilation** (open): every candidate is already a tree that the execution check found
equivalent, written by the emitter with no helpers, `volatile` or casts of its own; the explicit check of spec §15.4 is the
next increment.
